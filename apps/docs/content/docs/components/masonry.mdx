`Masonry` is the smallest layout mode. Use it when every item can render up
front and you do not need Masonix to measure item heights.

<ProductGridDemo />

## When to use

- Product grids, profile grids, link collections, and simple galleries.
- Layouts where source order should remain visually straightforward.
- Pages where all items are cheap enough to render.

## Basic usage

```tsx
import { Masonry } from 'masonix';

type Product = {
  id: string;
  name: string;
  category: string;
  price: string;
  rating: string;
  badge: string;
  gradient: string;
  height: number;
};

function ProductCard({ product }: { product: Product }) {
  return (
    <article className={cn('overflow-hidden', 'rounded-xl border', 'bg-white')}>
      <div
        className="relative"
        style={{ height: product.height, background: product.gradient }}
      >
        <span
          className={cn(
            'absolute left-3 top-3',
            'px-2 py-1',
            'rounded-full',
            'text-xs font-medium',
            'bg-white/85 text-zinc-900',
          )}
        >
          {product.badge}
        </span>
      </div>
      <div className="p-4">
        <div className="flex items-start justify-between gap-3">
          <div>
            <p className={cn('text-xs', 'text-zinc-500')}>{product.category}</p>
            <h3 className={cn('mt-1', 'text-sm font-semibold')}>
              {product.name}
            </h3>
          </div>
          <span className={cn('shrink-0', 'text-sm font-semibold')}>
            {product.price}
          </span>
        </div>
        <p className={cn('mt-3', 'text-xs', 'text-zinc-500')}>
          Rating {product.rating} / 5.0
        </p>
      </div>
    </article>
  );
}

export function ProductGrid({ products }: { products: Product[] }) {
  return (
    <Masonry
      items={products}
      columnWidth={180}
      maxColumns={3}
      gap={16}
      itemKey={(product) => product.id}
      render={MasonryCard}
    />
  );
}

function MasonryCard({
  data,
}: {
  data: React.ComponentProps<typeof ProductCard>['product'];
}) {
  return <ProductCard product={data} />;
}

function cn(...groups: string[]) {
  return groups.join(' ');
}
```

## Responsive columns

```tsx
<Masonry
  items={items}
  columns={{ 0: 1, 720: 2, 1080: 3, 1320: 4 }}
  gap={{ 0: 10, 720: 14, 1080: 18 }}
  render={MasonryCard}
/>;

function MasonryCard({
  data,
}: {
  data: React.ComponentProps<typeof Card>['item'];
}) {
  return <Card item={data} />;
}
```

Use `columns` when design requires exact counts. Use `columnWidth` when cards
should keep a minimum width and Masonix can decide how many columns fit.

## Native CSS masonry

`enableNative` lets Masonix use native CSS masonry when the browser supports
it. Unsupported browsers continue using the regular Masonix layout. The
container's `data-masonix-layout` attribute always reports `native` or
`fallback`.

```tsx
<Masonry
  enableNative
  items={items}
  columns={3}
  gap={16}
  onLayoutModeChange={(mode) => setLayoutMode(mode)}
  render={MasonryCard}
/>;

function MasonryCard({
  data,
}: {
  data: React.ComponentProps<typeof Card>['item'];
}) {
  return <Card item={data} />;
}
```

## Common mistakes

- Do not use `Masonry` for very large feeds where the DOM cost is the problem.
- Do not expect shortest-column balancing; use `MasonryBalanced` for that.
- Do not omit `itemKey` when items can filter, shuffle, or reorder.
